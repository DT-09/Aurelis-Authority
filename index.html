WHY AUTHORITY TESTING MATTERS

When an agent can act, permission becomes a business risk.

Teams need more than a reassuring answer from a model. They need to know whether the workflow blocks actions that exceed the authority it was given.

01 / FINANCIAL ACTIONS

Limits must hold at the point of action.

A refund agent may be told to request approval above a threshold. The question is whether the execution path actually prevents an unapproved refund.

Useful before: launching payments, refunds, purchasing or account changes.

02 / DATA ACCESS

Access must match the task.

An agent may reach records or tools beyond what its current task requires. Testing checks whether the intended boundary is clear and enforced in the workflow under review.

Useful before: connecting internal systems, customer records or new tools.

03 / CHANGE & RELEASE

Updates can change behavior.

A new model, tool, prompt or policy can alter the way an agent acts. Repeatable challenges help teams catch a boundary regression before release.

Useful before: a production pilot, major integration or agent update.

Inspect the evidence artifact.

This artifact comes from an actual run of the deliberately vulnerable demo agent against in-memory mock tools. It records the attempted call, gateway observation, execution trace, expected result, remediation, and a second run with enforcement enabled. The mock tools never contact external systems or change real data.

Baseline: the agent attempts all five actions; the mock gateway accepts them because enforcement is disabled. Retest: the same cases run with the enforcement gate enabled. Results are derived from each execution response, not manually assigned.

QUESTIONS BUYERS SHOULD ASK

Does the public demo test our agent?

No. It runs deterministic scenarios against in-memory mock tools. A client engagement must use a separately agreed and authorized test environment.

What will we receive?

The agreed package can include the scope and test plan, traceable results, findings, remediation recommendations, retest outcomes, and a technical readout. Exact contents are agreed before work begins.

How long does a pilot take?

Timeline depends on workflow complexity, test access, and the evidence required. We confirm a delivery schedule after scoping rather than publish an unsupported estimate.

What does it cost?

Commercial terms are discussed and agreed against the scope, access requirements, and deliverables before execution. There is no fixed public price.

Is this a certification or a guarantee of security?

No. Results apply only to the agreed scope, configuration, and test conditions. They do not certify a system or guarantee behavior outside the assessment.
